# Команда разработки

Главный агент выполняет функции Technical Lead: уточняет план, назначает владельцев файлов, интегрирует результаты, проверяет качество и единолично управляет Git.

## Специализации

- **Architect** — `.codex/agents/architect.toml`: границы компонентов, контракты, ADR и интеграционные риски.
- **Backend Engineer** — `.codex/agents/backend-engineer.toml`: API, бизнес-правила, транзакции и backend-проверки.
- **Database Engineer** — `.codex/agents/database-engineer.toml`: схема, ограничения, миграции, конкурентность и восстановление.
- **Frontend Engineer** — `.codex/agents/frontend-engineer.toml`: интерфейс, доступность, состояния взаимодействия и API-интеграция.
- **QA Engineer** — `.codex/agents/qa-engineer.toml`: критерии приёмки, воспроизведение дефектов и Playwright-доказательства.
- **Security Engineer** — `.codex/agents/security-engineer.toml`: границы доверия, авторизация, секреты, зависимости и сценарии злоупотребления.
- **DevOps Engineer** — `.codex/agents/devops-engineer.toml`: воспроизводимая среда, проектные контейнеры, CI и эксплуатационные проверки.
- **Technical Writer** — `.codex/agents/technical-writer.toml`: документация, состояние этапов и передача контекста.

Профили не фиксируют модель и наследуют настройки родительской сессии. Они не меняют полномочия, sandbox, провайдера или MCP-соединения.

## Конфигурация и запуск

Для установленного Codex CLI `0.172.0` используются самостоятельные TOML-файлы в `.codex/agents/` с полями `name`, `description`, `developer_instructions`. Формат проверен по [официальному руководству Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Проектный `.codex/config.toml` ограничивает `agents.max_concurrent_threads_per_session` значением `3`. Это консервативный лимит для четырёх доступных слотов вместе с главным агентом; пользовательский максимум в четыре субагента не превышается.

Синтаксис всех восьми профилей проверен Python `tomllib`. Вывод `codex debug prompt-input` подтверждает включение проектного `AGENTS.md` и всех восьми имён ролей в контекст клиента.

Инструмент запуска в текущем чате не предоставляет отдельный параметр выбора сохранённой роли. Поэтому при делегировании главный агент явно поручает прочитать соответствующий TOML-профиль и `AGENTS.md`. Фактический запуск такого субагента не следует описывать как проверенный нативный выбор профиля клиентом.

## Работа без конфликтов

Перед запуском главный агент задаёт задачу, разрешённые пути, критерии проверки и формат результата. На один файл назначается один исполнитель. Независимые реализации и чтение можно выполнять параллельно; общие изменения интегрирует главный агент.

Субагенты возвращают изменённые пути, поведение, реально выполненные проверки, риски и следующий шаг. Они не создают дополнительные субагенты и не выполняют commit, push, merge или смену ветки без отдельного назначения главного агента.
