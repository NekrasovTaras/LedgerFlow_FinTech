# Архитектура LedgerFlow

Статус: подготовка среды; полное техническое задание ещё не получено.

Рабочие архитектурные решения фиксируются в ADR в `decisions/`. Сейчас утверждена только граница подготовительного этапа: [ADR-0001](decisions/0001-bootstrap-boundary.md).

## Что уже определено

- Репозиторий хранит инструкции команды, планы, журнал прогресса и проверяемые инструменты разработки.
- Восемь проектных профилей Codex разделяют ответственность. Technical Lead управляет общими контрактами, интеграцией и Git.
- Playwright проверяет отдельную тестовую страницу. Это проверка инструментов наблюдения и тестирования, а не финансовое приложение.
- Данные тестового стенда синтетические. Секреты, локальные базы и записи тестов исключены из Git.

## Что определяется после получения ТЗ

1. Пользовательские роли, сценарии и критерии приёмки.
2. Финансовые сущности, валюты, точность, правила проводок, отмены и аудит.
3. Контракты API, границы транзакций, идемпотентность и конкурентные изменения.
4. Бэкенд, фронтенд, база данных, миграции и схема развёртывания.
5. Модель угроз, авторизация, изоляция данных и наблюдаемость.
6. Изолированные сценарии Chaos Lab, инварианты и доказательства восстановления.

Предположения должны быть явно помечены. Финансовые инварианты проверяются по утверждённым требованиям; готовность тестового стенда не доказывает их выполнение.
