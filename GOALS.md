# Цели LedgerFlow

## Текущий этап: подготовка завершена

Сформировать воспроизводимую среду, команду и постоянный контекст перед получением полного технического задания.

Все критерии ниже выполнены; доказательства и успешный первый CI записаны в `PROGRESS.md`. Следующая задача — приём полного ТЗ.

Критерии завершения подготовки:

- Проверены локальная среда, состояние и история Git, доступ к GitHub и Docker Engine.
- Созданы `.gitignore`, рабочая ветка `feat/ledgerflow-build` и проектная конфигурация Codex установленной версии.
- Определены восемь ролей; фактически запущен хотя бы один субагент.
- Созданы инструкции, цели, план, дорожная карта, журнал прогресса, changelog и архитектурные документы.
- Подготовлен и проверен Playwright headed mode с замедлением, скриншотами, видео и отчётами.
- Выполнены проверки первого логического блока, commit и push; фактический результат записан в `PROGRESS.md`.

## Активная цель: реализация полного ТЗ

Полное ТЗ получено 2026-11-24 и сохранено в `docs/requirements/MASTER_SPEC.md`. Реализовать модульный монолит с корректным PostgreSQL ledger, авторизацией, кошельками, платежами, идемпотентностью, outbox/inbox, локальными провайдерами, сверкой, Chaos Lab и рабочим React UI.

Стек задан ТЗ: Python 3.13/FastAPI/SQLAlchemy/PostgreSQL, Redis/RabbitMQ/Celery, React/TypeScript/Vite. Только виртуальные средства и локальные mock-сервисы. Проверочный стенд M0 не считается продуктом.

## Постоянные требования

- Работать только внутри LedgerFlow и проектных контейнеров.
- Не раскрывать секреты, не менять глобальные настройки безопасности и не выполнять force push.
- Разделять владение файлами между агентами; интеграцию и Git поручать главному агенту.
- Подтверждать результат реальными проверками и сохранять контекст после значимых этапов.
- Не выполнять автоматический merge в `main`.
